# No smart intelligent | 2026-10-25 (일) — Function Calling 복습

**오늘의 핵심 표현: The model requests a tool call; the application executes it.**

## 1. 오늘의 학술 용어와 근거

**Function calling(함수 호출)**은 모델에 사용 가능한 함수와 입력 형식을 알려주고, 모델이 함수 이름과 인자를 호출 요청으로 반환하도록 하는 방식이다. **애플리케이션 실행형** 함수 호출에서는 앱이 요청을 검증하고 실제 API·DB 조회를 실행한 뒤, 결과를 모델에 전달한다. 이는 모델이 스스로 ERP에 직접 접근하거나 권한을 취득한다는 뜻이 아니다. [S1](https://developers.openai.com/api/docs/guides/function-calling)

**관련 용어:** *Tool call*은 모델이 반환하는 도구 사용 요청이고, *tool result*는 실행 환경이 돌려주는 결과다. **가상 사례:** 구매 담당자가 공급업체 현황을 물으면 모델이 조회 함수를 요청하고 애플리케이션이 권한을 확인한 후 결과를 반환하도록 설계한다.

**오늘의 구별:** *제안된 행동 ≠ 허가된 실행*. 특히 데이터 **조회(read)**와 **변경(write)**은 별도의 도구 정의와 권한 검사를 요구할 수 있다. 또한 일부 제공자 내장 도구는 실행 주체가 다르므로 여기서는 애플리케이션 실행형으로 범위를 한정한다. [S1](https://developers.openai.com/api/docs/guides/function-calling) · [S3](https://www.anthropic.com/research/trustworthy-agents)

**확인한 원문 발췌(OpenAI):** “you must execute it and return the result.” 이 구절은 애플리케이션이 함수 실행과 결과 반환을 맡는 단계를 뜻한다. 2번의 E1 표현으로 역할을 더 명확하게 풀어 말한다. [S1](https://developers.openai.com/api/docs/guides/function-calling)

**근거 자료:** [S1] OpenAI, *Function calling* (공식 구현 가이드, 게시일 미확인): 모델 요청·인자·앱 실행·결과 반환. [원문](https://developers.openai.com/api/docs/guides/function-calling) · [S2] Anthropic Engineering, *Building effective agents* (2024-12-19, 설계 해설): workflow와 agent의 도구 사용·실행 경로 구별. [원문](https://www.anthropic.com/research/building-effective-agents) · [S3] Anthropic Frontier Red Team, *Trustworthy agents in practice* (2026-04-09, 연구·안전 해설): 사용자 통제와 도구 권한. [원문](https://www.anthropic.com/research/trustworthy-agents)

## 2. 고객에게 설명하는 영어

*오늘은 앞서 제공한 2026-10-24 표현을 새로운 구매 업무 예시로 복습한다. 해당 수업의 사용자 답변 완료는 확인되지 않았다. 다음은 원문 인용이 아닌 설명용 재작성이다.*

**1. 핵심 · The model requests a tool call; the application executes it.**  
> In this proposed purchasing assistant, the model requests a tool call, and the application executes the supplier-status lookup.

제안하는 구매 보조 시스템에서 모델은 도구 호출을 요청하고 애플리케이션은 공급업체 상태 조회를 실행합니다. 모델의 요청과 실제 실행 주체를 구분할 때. ([S1](https://developers.openai.com/api/docs/guides/function-calling))

**2. 확장 · Define a tool with clear input parameters**  
> We define a supplier-status function with a supplier ID as its required input.

공급업체 ID를 필수 입력값으로 사용하는 상태 조회 함수를 정의합니다. 도구 명세와 필요한 입력값을 설명할 때. ([S1](https://developers.openai.com/api/docs/guides/function-calling))

**3. 확장 · Pass structured arguments to a function**  
> The model supplies structured arguments so the application can identify the requested supplier.

모델은 애플리케이션이 조회 대상 공급업체를 식별할 수 있도록 구조화된 인자를 제공합니다. 일반 문장과 함수 호출용 입력의 차이를 설명할 때. ([S1](https://developers.openai.com/api/docs/guides/function-calling))

**4. 확장 · Return the tool result to the model**  
> After the lookup finishes, the application returns the tool result to the model.

조회가 끝나면 애플리케이션은 도구 결과를 모델에 다시 전달합니다. 실행 후 반환 데이터의 흐름을 설명할 때. ([S1](https://developers.openai.com/api/docs/guides/function-calling))

**5. 확장 · Use the returned data to draft …**  
> The model uses the returned data to draft a status summary for the buyer.

모델은 반환된 데이터를 활용해 구매 담당자에게 제공할 상태 요약 초안을 작성합니다. 조회 결과와 생성 결과를 연결할 때. 사실 정확성은 별도 확인이 필요. ([S1](https://developers.openai.com/api/docs/guides/function-calling))

**6. 확장 · Restrict the tools available to the model**  
> We restrict the tools available to the model to supplier lookups in this proposed workflow.

이 제안 워크플로에서는 모델이 사용할 수 있는 도구를 공급업체 조회로 제한합니다. 모델에 공개하는 도구 범위와 실제 백엔드 권한의 차이를 설명할 때. ([S1](https://developers.openai.com/api/docs/guides/function-calling) · [S3](https://www.anthropic.com/research/trustworthy-agents))

**청중별 변형 — 임원:** “The assistant can draft a supplier update from approved lookups, but it cannot change purchase orders unless we build and authorize that action.”  
보조 시스템은 허용된 조회 결과를 활용해 공급업체 현황 초안을 작성할 수 있지만, 별도의 변경 기능과 권한을 설계하지 않는 한 발주서를 변경할 수 없습니다. ([S1](https://developers.openai.com/api/docs/guides/function-calling) · [S3](https://www.anthropic.com/research/trustworthy-agents))

**청중별 변형 — 기술팀:** “The model proposes a function name and arguments; in this design, the backend checks access rights, runs the lookup, and sends the result back.”  
모델이 함수 이름과 인자를 제시하면, 이 설계에서 백엔드는 접근 권한을 확인하고 조회를 실행한 뒤 결과를 다시 전달합니다. ([S1](https://developers.openai.com/api/docs/guides/function-calling) · [S3](https://www.anthropic.com/research/trustworthy-agents))

## 3. 오늘의 한 문제

**가상 업무 상황:** 가상의 물류 회사. Agent가 선적 상태를 읽을 수는 있지만 납기 변경 기능은 아직 승인되지 않았다. 고객 임원은 왜 조회와 변경을 분리하는지 묻는다.

**Customer:** “If the agent can check a shipment's status, why shouldn't it automatically change the delivery date in our system?”

**Your task:** 영어 3~5문장(약 40~70단어 또는 말하기 30~45초)으로 설명한다. **필수:** *The model requests a tool call; the application executes it.* **선택:** *Return the tool result to the model* 또는 *Restrict the tools available to the model*. 문장 구조는 상황에 맞게 변형할 수 있다. 조회와 변경을 누가 실행·허가하는지, 왜 구분해야 하는지 설명하되 실제 구현을 주장하지 않는다.
