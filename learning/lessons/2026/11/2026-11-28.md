# No Smart Intelligent | 2026.11.28 (토) — Position Bias in LLM-as-a-Judge

**Test whether the judge favors a response because of its position rather than its quality.**

약 10분 학습 · 핵심 표현 1개 + 확장 5개 · 청중별 예문 2개

## 1. 오늘의 학술 용어와 근거

**Position bias in LLM-as-a-judge — LLM 평가자의 위치 편향(풀이)**

두 답변을 비교하는 LLM 평가자가 답변의 실제 품질과 무관하게 프롬프트에서 특정 위치에 있는 답변을 체계적으로 선호하는 경향입니다. 같은 답변 쌍의 순서만 바꾸어 비교하고, 동일 입력 반복 평가로 무작위 변동과 구별할 수 있습니다. [S1](https://developers.openai.com/api/docs/guides/evaluation-best-practices) [S2](https://arxiv.org/html/2406.07791v9)

관련 용어: **Pairwise comparison(쌍대 비교)** — 두 답변을 평가 기준에 따라 비교하는 방식. **Position consistency(위치 일관성, 풀이)** — 답변의 순서를 바꾸어도 동일한 답변을 선호하는 정도.

**가상 업무 사례 — 공급업체 요약 비교**

| 평가 순서 | 첫 번째 답변 | 두 번째 답변 | 평가자의 선택 |
| --- | --- | --- | --- |
| 1차 | 요약 X | 요약 Y | X |
| 2차 | 요약 Y | 요약 X | Y |

두 번 모두 첫 번째 답변이 선택되었습니다. 위치 영향이 의심되지만 이 한 쌍의 결과만으로 체계적 편향을 확정할 수는 없습니다. 여러 답변 쌍과 동일 입력 반복 평가가 필요합니다.

**중요한 구별 — Position consistency ≠ Accuracy**

순서 일관성은 정확성과 다릅니다. 순서를 바꾸어도 같은 답변을 선택하는 평가자가 사람의 기준에서 더 나쁜 답변을 고를 수 있으므로 전문가 라벨로 별도 검증해야 합니다. [S1](https://developers.openai.com/api/docs/guides/evaluation-best-practices) [S2](https://arxiv.org/html/2406.07791v9)

**원문 요지 → 설명용 재작성:** Dartmouth 연구에서는 같은 답변 쌍의 순서를 교환해 평가자가 특정 위치가 아니라 같은 답변을 계속 선택하는지를 확인합니다. 이를 E1의 “Test whether the judge favors a response because of its position rather than its quality”로 재작성했습니다. 직접 인용이 아닙니다. [S2](https://arxiv.org/html/2406.07791v9)

## 2. 고객에게 설명하는 영어

**E1. Test whether the judge favors a response because of its position rather than its quality** (핵심)

Position bias occurs when an LLM judge favors a response because of where it appears in the prompt rather than how well it meets the evaluation criteria.

위치 편향은 LLM 평가자가 평가 기준 충족 정도보다 프롬프트에서 답변이 놓인 위치 때문에 특정 답변을 선호할 때 발생합니다. 활용: 자동 평가의 편향을 정의할 때. [S1](https://developers.openai.com/api/docs/guides/evaluation-best-practices) [S2](https://arxiv.org/html/2406.07791v9)

**E2. Swap the presentation order while keeping the responses unchanged**

We would show the same two supplier-summary responses in both orders without changing their content.

동일한 공급업체 요약 답변 두 개의 내용을 변경하지 않고 두 가지 순서로 제시하겠습니다. 활용: 순서의 영향을 확인하는 실험을 설계할 때. [S2](https://arxiv.org/html/2406.07791v9)

**E3. Apply the same success criteria across trials**

We would apply the same success criteria across trials, including whether each summary retains the required facts from the source documents.

각 요약에 원문 필수 사실이 유지되었는지를 포함해 모든 시도에 동일한 성공 기준을 적용하겠습니다. 활용: 평가 기준을 고정할 때. 11월 25일에 제공한 표현의 복습. [S1](https://developers.openai.com/api/docs/guides/evaluation-best-practices) [S2](https://arxiv.org/html/2406.07791v9)

**E4. Map each verdict back to the original response identity**

We would map each verdict back to the original response identity before checking whether the preferred summary has changed.

선호 요약이 바뀌었는지 확인하기 전에 각 판정을 원래 답변의 식별자에 대응시키겠습니다. 활용: 첫 번째/두 번째 위치와 실제 답변을 혼동하지 않도록 할 때. [S2](https://arxiv.org/html/2406.07791v9)

**E5. Flag order-sensitive judgments for human review**

If the preferred supplier summary changes when the order is reversed, we would flag that comparison for human review.

순서를 바꿨을 때 선호하는 공급업체 요약이 달라지면 해당 비교를 사람의 검토 대상으로 표시하겠습니다. 활용: 상충하는 평가 결과의 처리 정책을 제안할 때. [S2](https://arxiv.org/html/2406.07791v9) [S1](https://developers.openai.com/api/docs/guides/evaluation-best-practices)

**E6. Validate judge agreement against expert-labeled examples**

We would compare the judge's preferences with expert labels before using its scores to select a production model.

운영 모델을 선정하는 데 평가 점수를 사용하기 전에 전문가 라벨과 평가자의 선호 결과를 비교하겠습니다. 활용: 자동 평가 결과를 신뢰할 수 있는지 검증할 때. [S1](https://developers.openai.com/api/docs/guides/evaluation-best-practices)

**청중별 변형**

**Example 7 — For Business executives**

We would check that the evaluator chooses the better supplier summary even when the two answers change places, and confirm its decisions with expert reviewers.

두 답변의 위치가 바뀌어도 평가자가 더 좋은 공급업체 요약을 선택하는지 확인하고 전문가 검토로 판정을 검증하겠습니다. [S1](https://developers.openai.com/api/docs/guides/evaluation-best-practices) [S2](https://arxiv.org/html/2406.07791v9)

**Example 8 — For Technical teams**

We would run blinded pairwise comparisons in both orders, repeat identical prompts to estimate variability, and measure order consistency and agreement with expert labels.

모델의 신원을 숨긴 쌍대 비교를 두 순서로 실시하고 동일 프롬프트를 반복해 변동성을 추정하며 순서 일관성과 전문가 라벨 일치율을 측정하겠습니다. [S1](https://developers.openai.com/api/docs/guides/evaluation-best-practices) [S2](https://arxiv.org/html/2406.07791v9)

## 3. 오늘의 한 문제

**Consultant's Challenge — Expense-report summary evaluation**

가상의 금융회사가 두 AI 모델의 내부 비용 보고서 요약 품질을 비교합니다. 자동 평가에서 모델 A의 답변을 항상 첫 번째에 배치했으며 사람이 검토한 비교 자료도 아직 충분하지 않습니다.

**Customer Question**

“Our automated judge always sees Model A's expense-report summary first and usually selects it as the winner. How would you determine whether Model A is genuinely better or simply benefits from its position?”

**필수 표현:** Test whether the judge favors a response because of its position rather than its quality

**선택 표현:** E3 — Apply the same success criteria across trials / E6 — Validate judge agreement against expert-labeled examples

영어 3~5문장, 약 40~70단어 또는 30~45초. 핵심 E1과 E3 또는 E6 중 하나를 자연스럽게 변형해 사용하세요. 위치 편향의 의미, 답변 내용은 유지하면서 순서를 바꾸는 비교 방법, 그리고 순서 일관성만으로 품질 우위를 확정할 수 없는 이유를 포함하세요. E3은 11월 25일에 제공한 표현의 복습입니다.
