# No Smart Intelligent | 2026-11-11 (수) — ReAct (Reasoning and Acting)

**Today's Key Expression: “Interleave reasoning, tool actions, and observations to adapt the next step.”**

약 10분 학습 · 핵심 표현 1개 + 확장 5개 · 청중별 예문 2개

## 1. 오늘의 학술 용어와 근거

### ReAct (Reasoning and Acting) — 추론과 행동의 결합(풀이)

**ReAct**는 언어모델이 작업 중 추론을 나타내는 텍스트, 외부 도구를 향한 행동, 도구가 돌려준 관측 결과를 교차 활용하도록 설계한 **연구 기반의 문제 해결 접근**입니다. 관측 결과가 다음 단계의 판단과 행동 계획을 수정하는 데 쓰이므로, 처음 정한 계획만 끝까지 따르는 방식과 다릅니다. 다만 ReAct 형식을 사용한다고 결과의 정확성이나 외부 시스템 변경 권한이 자동으로 보장되지는 않습니다. **[S1]**

**관련 용어 두 개:** **Action(행동)**은 검색·조회처럼 외부 환경에 요청하는 작업이며, **Observation(관측 결과)**은 그 실행 이후 시스템에서 되돌아오는 결과입니다. 모델이 다음에 무엇을 할지 *제안*하는 일과 실제 도구가 수행된 뒤 결과를 *받는* 일은 구분됩니다.

**가상 업무 사례 — 선적 지연 조사:** 물류 보조 에이전트가 지연된 주문의 최신 운송 상태를 조회한다고 가정하겠습니다. 관측 결과가 ‘세관 보류’라면 기존 운송 일정 조회를 반복하기보다 필요한 통관 서류를 확인하도록 다음 행동을 바꿀 수 있습니다. 하지만 관측 정보가 오래됐거나 오류가 있다면 그 결과를 그대로 확정 보고해서는 안 되며, 계약 내용 변경에는 별도 승인 절차가 필요합니다.

**오늘의 구별 — ReAct형 에이전트 루프 ≠ 고정 워크플로:** 고정 워크플로는 프로그램에 정의된 경로를 따르는 데 적합합니다. 반면 어떤 도구를 다음에 사용할지 관측에 따라 달라지는 과제는 에이전트 루프가 유용할 수 있습니다. Anthropic은 유연성의 대가로 지연·비용·오류 위험이 늘 수 있으므로, 더 단순한 방식으로 충분하다면 굳이 에이전트를 채택하지 말 것을 권고합니다. **[S2]**

**원문 발췌 [S1]:** “reasoning traces and text actions in an interleaved manner”. 이는 추론과 도구 행동을 **교차**시킨다는 연구의 핵심 표현입니다. 고객 설명용 재작성은 **“Interleave reasoning, tool actions, and observations to adapt the next step.”**로, 여기에 도구에서 돌아온 결과가 다음 판단을 바꾼다는 작동 의미를 포함했습니다. 원 연구는 여러 과제에서 프롬프트 방식과 미세조정 방식을 연구했으며, 모든 에이전트가 동일한 구현을 사용한다는 뜻은 아닙니다.

**오늘 확인한 공식 자료**

**[S1] Google Research**, Shunyu Yao·Yuan Cao, *ReAct: Synergizing Reasoning and Acting in Language Models* (**2022-11-08**). 공식 연구 해설. 추론·행동·관측의 순환, 검색 결과를 반영한 행동 선택, 실험 과제와 한계를 확인했습니다. [원문](https://research.google/blog/react-synergizing-reasoning-and-acting-in-language-models/).

**[S2] Anthropic Engineering**, *Building effective agents* (**2024-12-19**). 공식 엔지니어링 설계 권고. 에이전트와 고정 워크플로의 차이, 환경 피드백, 사람의 판단과 종료 조건, 비용·오류 절충을 확인했습니다. [원문](https://www.anthropic.com/research/building-effective-agents).

## 2. 고객에게 설명하는 영어

아래 여덟 문장은 위 자료의 작동 원리를 바탕으로 새로 작성한 **설명용 영어 및 가상 사례**입니다. 실제 고객사의 구현이나 성과를 나타내지 않습니다.

**⭐ 핵심 1 — Interleave reasoning, tool actions, and observations to adapt the next step**

> ReAct interleaves reasoning with tool actions and observations so the next step can reflect newly retrieved information.

**해석:** ReAct는 추론과 도구 행동 및 관측 결과를 교차 활용하여 새로 확인한 정보에 맞춰 다음 단계를 조정합니다. **활용:** 연구의 핵심 메커니즘을 정의할 때. (S1)

**확장 2 — Request external information before choosing the next action**

> For a delayed shipment, the agent would check the latest tracking event before selecting another investigation step.

**해석:** 선적이 지연되면 에이전트는 다음 조사 단계를 선택하기 전에 최신 추적 기록을 확인하겠습니다. **활용:** 외부 시스템 조회가 필요한 이유를 설명할 때. (S1·S2)

**확장 3 — Use observations to revise the action plan**

> If the carrier reports a customs hold, the agent revises its plan and checks the missing documentation instead of repeating the original lookup.

**해석:** 운송사가 세관 보류를 보고하면 에이전트는 기존 조회를 반복하는 대신 계획을 바꾸어 누락 서류를 확인합니다. **활용:** 도구 결과에 따른 동적 재계획을 설명할 때. (S1)

**확장 4 — Distinguish an adaptive agent loop from a fixed workflow**

> A fixed workflow follows predefined steps, whereas an adaptive agent loop chooses later actions using observations from earlier steps.

**해석:** 고정 워크플로는 사전에 정해진 단계를 따르지만, 적응형 에이전트 루프는 앞선 관측 결과로 다음 행동을 선택합니다. **활용:** 업무를 워크플로로 만들지 에이전트로 만들지 논의할 때. (S2)

**확장 5 — Check tool outputs before using them to make decisions**

> We would check the timestamp and status fields in a tracking response before drafting an update for the logistics team.

**해석:** 물류팀에 업데이트를 작성하기 전에 추적 응답의 시각과 상태 필드를 점검하겠습니다. **활용:** 도구 관측값의 신뢰성을 검토하는 설계를 제안할 때. (S1·S2)

**확장 6 — Set a stopping condition for repeated tool calls**

> We would stop after a defined number of checks and request human review if the shipment discrepancy remains unresolved.

**해석:** 정해진 횟수만큼 확인한 뒤에도 선적 정보 불일치가 해결되지 않으면 중단하고 사람의 검토를 요청하겠습니다. **활용:** 비용·반복 오류를 통제하는 운영 한계를 설명할 때. (S2)

**청중별 설명 — 임원/비전공 현업용**

> The assistant can adjust its next check when shipment information changes, but we would still require approval before changing contractual records.

**해석:** 배송 정보가 달라지면 보조 시스템이 다음 확인 항목을 조정할 수 있지만, 계약 기록 변경에는 여전히 승인이 필요합니다. 신속한 조사와 계약 기록 변경에 필요한 승인 책임을 구분해 설명합니다.

**청중별 설명 — 기술팀용**

> We would log action-observation pairs, test recovery from tool errors, and cap the loop length to control repeated failures and cost.

**해석:** 행동과 관측 결과의 쌍을 기록하고 도구 오류 복구를 시험하며, 반복 실패와 비용을 통제하도록 루프 길이에 상한을 두겠습니다. 실행 로그, 오류 처리, 중단 조건을 기술 검증 기준으로 제안합니다.

## 3. 오늘의 한 문제

**Consultant's Challenge — Invoice Discrepancy Investigation (가상 상황)**

가상의 소프트웨어 기업에서 청구서 금액이 계약 기록과 다르게 나타났다. AI에는 계약 조회·가격표 조회·결제 내역 조회 도구가 있지만 원인은 아직 확인되지 않았다. 수정은 사람 승인 이후에만 가능하다.

**Customer Question**

> Our invoice agent sees a mismatch between the contract price and the billed amount. How should it decide which system to check next, and when should it stop rather than change the invoice?

영어 **3~5문장, 약 40~70단어** 또는 **30~45초**로 답하세요. 단순히 도구가 여러 개 있다는 설명이 아니라, 관측 결과를 사용해 다음 확인 순서를 어떻게 바꿀지 설명해야 합니다.

**필수 표현:** “Interleave reasoning, tool actions, and observations to adapt the next step.”

**선택 표현(한 개만):** “Use observations to revise the action plan” 또는 “Set a stopping condition for repeated tool calls”.

관측을 활용한 계획 수정과 사람이 승인해야 하는 변경의 한계를 담으세요. 앞서 제공한 11월 8일 Grounding 표현을 떠올려 근거가 충분한지 검토해도 좋지만, 세 번째 영어 패턴을 사용할 필요는 없습니다. 답변 전에는 자동 수정이나 정확한 원인 확인을 보장하지 마세요.
